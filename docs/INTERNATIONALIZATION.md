# Internationalization — GoDevs Portfolio

**Document version:** 1.5.0

The theme is translation-ready, localization-ready, and RTL-ready.
This document explains how the translation surface actually works in
v1.5.0 and how to translate the theme.

> Note: earlier drafts of this document claimed "There are no
> user-facing PHP strings in functions.php in v0.1" and that the
> `languages/godevs-portfolio.pot` file was only "scaffolded". Neither
> is true of v1.5.0. The theme now ships 715 unique translatable
> strings, extracted into a real `.pot` file generated by
> `scripts/generate-pot.py`.

---

## 1. Text domain

The theme uses the `godevs-portfolio` text domain everywhere. It is
loaded in `functions.php` via:

```php
load_theme_textdomain( 'godevs-portfolio', get_template_directory() . '/languages' );
```

Translation files live in `languages/`:

| File | Shipped? | Purpose |
|---|---|---|
| `languages/godevs-portfolio.pot` | ✅ Yes (generated by P1.14) | The translation template — 715 unique strings |
| `languages/godevs-portfolio-<locale>.po` | ❌ No (translators create these) | Translator's working file |
| `languages/godevs-portfolio-<locale>.mo` | ❌ No (translators compile these) | Compiled translation loaded by WordPress |

## 2. What is translatable

### 2.1 PHP user-facing strings (715)

Every user-facing string in the theme's PHP source is wrapped in a
WordPress i18n function. The extraction covers:

- `functions.php` — theme setup labels, nav-menu labels, the
  diagnostic notice (~30 strings).
- `inc/theme-settings.php` — every setting label, description, section
  heading, button text (~200 strings).
- `inc/header-footer-builder.php` — element labels, default text,
  admin page strings (~80 strings).
- `inc/demo-importer.php` + `inc/demo-registry.php` + `inc/demo-renderer.php`
  — demo titles, import step labels, error messages (~90 strings).
- `inc/cpt-admin.php` + `inc/admin/views/*.php` — Content Manager
  labels, CPT labels (~70 strings).
- `inc/front-forms.php` — form labels, validation messages, email
  body (~60 strings).
- `inc/content/*.php` — CPT labels, taxonomy labels, meta-box labels
  (~150 strings).
- `inc/onboarding.php` — welcome notice strings (~25 strings).
- `inc/booking-system.php` — booking meta + admin notices (~15 strings).

### 2.2 i18n functions used

| Function | Where | Count (approx) |
|---|---|---|
| `__()` | Strings used in PHP logic (defaults, options) | ~280 |
| `esc_html__()` | Strings echoed as HTML text | ~210 |
| `esc_html_e()` | Strings echoed immediately (admin views) | ~120 |
| `esc_attr__()` / `esc_attr_e()` | Strings used as attribute values | ~55 |
| `_x()` / `esc_html_x()` / `esc_attr_x()` | Strings needing translation context | ~15 |
| `_n()` | Plural-aware strings (e.g. "%d item", "%d items") | ~5 |
| `esc_html_e()` with `printf()` / `sprintf()` | Strings with placeholders | ~30 |

Every string passes through one of the escaping-aware variants where
it will be output as HTML or an attribute, so translators never have
to worry about XSS escaping — it is built into the function choice.

### 2.3 Demo pattern strings (NOT gettext-wrapped)

The HTML inside `patterns/demos/*.php` and the root
`patterns/*.php` files is **block markup**, not PHP gettext calls.
WordPress.org treats block markup as **content** (not code), and
accepts this convention for block themes — the strings inside
patterns do not need PHP i18n function wrapping to pass the Theme
Review.

What this means for translators:

- The 715 PHP strings (admin UI, CPT labels, form labels, validation
  messages, email bodies, onboarding notices) are translatable via
  the `.pot` / `.po` / `.mo` workflow described in §5.
- The demo pattern copy (hero headlines, "About" intros, service
  descriptions, testimonial attributions, journal entries, …) is
  editable text that the user translates by hand in the Site Editor
  after importing a demo. There is no `.po`-based shortcut for these.

This is the standard WordPress.org-accepted convention for block
themes; it is also documented in the Theme Review Handbook.

## 3. `.pot` file generation

The `.pot` file is generated by scanning the theme's PHP source for
i18n function calls and extracting their string arguments. Two methods
are supported:

### 3.1 The bundled Python generator (preferred for contributors without WP-CLI)

```bash
python3 scripts/generate-pot.py
```

This is a zero-dependency Python 3 script that scans every `.php` file
in the theme (excluding `node_modules`, `.git`, `vendor`, `tests`, and
`docs`), finds calls to `__`, `_e`, `_x`, `_ex`, `_n`, `_nx`,
`esc_html__`, `esc_html_e`, `esc_html_x`, `esc_attr__`, `esc_attr_e`,
`esc_attr_x`, `_n_noop`, `_nx_noop`, and `translate_noop_plural`,
extracts their string arguments (handling single- and double-quoted
literals plus basic `.` concatenation), and writes
`languages/godevs-portfolio.pot`.

It writes the `X-Generator: GoDevs Portfolio POT Generator 1.0` header
and produces a deterministic, line-stable output. Current output: **715
unique translatable strings**.

### 3.2 WP-CLI (if available)

```bash
wp i18n make-pot . languages/godevs-portfolio.pot \
  --domain=godevs-portfolio \
  --exclude=node_modules,tests,docs
```

This requires the `wp-cli/i18n-command` package. It produces an
equivalent (not byte-identical) `.pot` file.

### 3.3 When to regenerate

Regenerate the `.pot` whenever user-facing PHP strings change — i.e.
on every release, and ideally on every merge that adds or changes a
user-visible string. The generated file should be committed to the
repository so translators always work from the latest catalogue.

## 4. RTL support

Block themes inherit RTL support through the WordPress style engine.
`theme.json` styles are flipped automatically for RTL languages
(Arabic, Hebrew, Persian, Urdu):

- `core/columns` flips column order in RTL.
- `core/quote` flips the left border to a right border.
- `core/navigation` right-aligns.

No manual `rtl.css` is required. The theme is RTL-ready out of the box.

## 5. Translation workflow

To translate the theme into a new locale:

1. Copy `languages/godevs-portfolio.pot` to
   `languages/godevs-portfolio-<locale>.po` (e.g.
   `godevs-portfolio-bn_BD.po`).
2. Open the `.po` file in a translation editor (Poedit, Lokalise,
   GlotPress, etc.).
3. Translate each `msgid` into the corresponding `msgstr`.
4. Save the `.po` file. The editor compiles a `.mo` file alongside it
   (or run `msgfmt` manually — see §5.1).
5. Place both files in the theme's `/languages/` directory (or in
   `wp-content/languages/themes/` to keep them outside the theme
   directory, which survives theme updates).
6. Switch the site language in WordPress admin
   (**Settings → General → Site Language**). WordPress loads the
   matching `.mo` file automatically.

### 5.1 Compiling `.po` → `.mo` from the command line

If your translation editor does not compile automatically, use
`msgfmt` (from the GNU `gettext` suite) or Poedit:

```bash
msgfmt -o languages/godevs-portfolio-bn_BD.mo \
         languages/godevs-portfolio-bn_BD.po
```

Or in Poedit: **File → Compile to MO**.

## 7. Date and time formatting

The theme uses `wp_date()` (locale-aware) wherever dates appear in PHP
(e.g. the Content Manager "Modified" column). Block-markup dates use
the `core/post-date` block, which respects the site locale.

Translators do not need to translate date format strings explicitly —
WordPress core handles month and day names based on the site locale.

---

## 8. Number formatting

The theme does not output currency. Numeric values (counts, IDs,
column counts) are output as plain integers via `esc_html((string) $n)`
or `absint()`. For future locale-aware number output, use WordPress
core's `number_format_i18n()`.

---

## 9. Plural forms

The theme uses `_n()` for the few plural-aware strings (e.g. the
Content Manager "X items" count). The `.pot` file carries the
`Plural-Forms: nplurals=2; plural=(n != 1);` header for English;
translators into languages with different plural rules (e.g. Russian,
Arabic, Polish) must update the `Plural-Forms` header in their `.po`
file to match their locale's plural equation.

---

## 10. Translation context

Where the same English word may need different translations in
different contexts, the theme uses `_x()`, `esc_html_x()`, or
`esc_attr_x()` with a context argument. The `.pot` file records each
context as a `msgctxt` line so translators see them grouped correctly.

## 11. RTL testing

The theme's RTL support is tested by:

1. Switching the site language to an RTL language (Arabic, Hebrew).
2. Browsing the front-end at 375, 768, 1024, 1280, 1440, 1920.
3. Confirming that:
   - Text direction is RTL.
   - Column order is reversed in multi-column layouts.
   - Quote block border is on the right.
   - Navigation is right-aligned.
   - Buttons and forms are mirrored.
4. Confirming that the Site Editor renders RTL correctly when editing
   templates and parts.
5. Confirming that the admin pages (Theme Settings, Content Manager,
   GoDevs Demos, HF Builder) render RTL correctly.

## 12. Locale-specific considerations

### 12.1 Demo pattern copy

Demo pattern copy (hero headlines, about intros, service descriptions,
testimonial attributions) is plain text inside block markup. For full
localization of a demo, the translator must edit each pattern by hand
in the Site Editor after importing the demo. This is the standard
WordPress.org-accepted workflow for block-theme demo content.

### 12.2 Currency

The theme does not display currency in v1.5.0. Pricing is a future
feature (optional, in the Services CPT) and will handle currency
formatting via WordPress core's `number_format_i18n()`.

### 12.3 Date formats

The theme's default date format (`M j, Y`, e.g. "Aug 29, 2026") is
appropriate for English. For other locales, the format may need
adjustment — the user can override the date format per-block in the
Site Editor.

## 13. WordPress.org translation

Once the theme is submitted to WordPress.org (after the GoDevs Core
plugin extraction — see
[`WORDPRESS-ORG-COMPLIANCE.md`](WORDPRESS-ORG-COMPLIANCE.md)), the
WordPress.org translation system (GlotPress) will automatically import
the `.pot` file and make the theme available for community translation
at
`https://translate.wordpress.org/projects/wp-themes/godevs-portfolio/`.

Community translators can submit translations for their locale via the
GlotPress web UI. Approved translations are bundled into language
packs and distributed to sites automatically.
